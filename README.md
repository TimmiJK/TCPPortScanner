# TCP-сканирование портов

Go-пакет `portscan` проверяет доступность TCP-портов через обычное установление соединения. Поддерживаются IPv4, IPv6, DNS-имена, списки и диапазоны портов, ограничение конкурентности и отмена через `context.Context`.

Требуется **Go 1.25.5**. Используется только стандартная библиотека. Пакет находится в `portscan/`, консольный пример - в `main.go`. Пакет можно импортировать в другие Go-приложения.

## Быстрый запуск

Из корня проекта можно запустить проверку портов локального компьютера.

```powershell
go run . -hosts 127.0.0.1 -ports 22,80,443 -concurrency 10 -timeout 2s
```

Пример для DNS-имени и диапазона портов:

```powershell
go run . -hosts google.com -ports 443,8443,8000-8010 -concurrency 10 -timeout 5s
```

Несколько хостов передаются через запятую. IPv6 указывается без квадратных скобок.

```powershell
go run . -hosts "127.0.0.1,::1,localhost" -ports "80,443,8000-8005"
```

`Ctrl+C` отменяет сканирование. Результаты выводятся по мере готовности. Значения по умолчанию - `127.0.0.1`, порты `80,443`, конкурентность `100`, таймаут `1s`. Справка доступна через `go run . -h`.

Ошибки отдельных подключений выводятся в результатах. Некорректные аргументы и прерывание завершают пример с ненулевым кодом выхода.

## Использование пакета

```go
package main

import (
    "context"
    "fmt"
    "log"
    "time"

    "tcp-scanner/portscan"
)

func main() {
    scanner, err := portscan.New(100, 500*time.Millisecond)
    if err != nil {
        log.Print(err)
        return
    }

    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()

    results, err := scanner.Scan(
        ctx,
        []string{"127.0.0.1", "::1"},
        portscan.Range(22, 22),
        portscan.Range(80, 90),
        portscan.Range(443, 443),
    )
    if err != nil {
        log.Print(err)
        return
    }

    for result := range results {
        fmt.Printf("host=%s ip=%v port=%d state=%s duration=%s err=%v\n",
            result.Host, result.IP, result.Port,
            result.State, result.Duration, result.Err)
    }
    if err := ctx.Err(); err != nil {
        log.Printf("scan interrupted: %v", err)
    }
}
```

`tcp-scanner` - локальный путь модуля из `go.mod`. После публикации репозитория для установки из других проектов замените его на адрес репозитория и обновите импорты в исходниках и тестах.

## Публичный API

```go
func New(concurrency int, connectTimeout time.Duration) (*Scanner, error)
func Range(from, to int) PortRange

type PortRange struct {
    From int
    To   int
}

func (s *Scanner) Scan(
    ctx context.Context,
    hosts []string,
    ranges ...PortRange,
) (<-chan Result, error)

func (s *Scanner) CheckPort(
    ctx context.Context,
    host string,
    ip net.IP,
    port uint16,
) Result

type Result struct {
    Host     string
    IP       net.IP
    Port     uint16
    State    State
    Duration time.Duration
    Err      error
}
```

`New` принимает положительные конкурентность и таймаут. Экземпляр создаётся через `New`; нулевой `Scanner` возвращает ошибку.

`Range` описывает включительные границы. `Range(443, 443)` задаёт одиночный порт. Несколько диапазонов и одиночных портов передаются отдельными аргументами. Можно передать срез `[]PortRange` через `ranges...`. Валидация выполняется в `Scan` до запуска горутин.

`CheckPort` для отдельной проверки уже известного IP. Для создания IP используйте `net.ParseIP`, например `net.ParseIP("127.0.0.1")`. Параметр `host` служит меткой результата. Невалидный IP и порт `0` дают `StateError`. Оба метода используют общий лимит подключений.

`Duration` измеряет попытку TCP-подключения, включая завершение по таймауту. Ожидание свободного слота, DNS, отправка результата и закрытие соединения в неё не входят. Если подключение не начиналось, длительность равна нулю.

## Входные данные и DNS

| Случай | Поведение |
|---|---|
| Пустой список хостов | Синхронная ошибка `Scan` |
| Пустая строка или пробелы | Синхронная ошибка `Scan` |
| Пробелы вокруг хоста | Удаляются |
| Невалидный IP или формат хоста | Синхронная ошибка `Scan` |
| Повторяющийся IP | Одна цель, включая эквивалентные записи IPv6 и IPv4-mapped IPv6 |
| Повторяющееся DNS-имя | Одна цель без учёта регистра и конечной точки, сохраняется первая запись |
| Несколько уникальных IP у DNS-имени | Проверяется каждый IP и каждый порт |
| Повторяющиеся IP в DNS-ответе | Удаляются |
| Разные имена указывают на один IP | Каждое имя обрабатывается отдельно |
| Пустой DNS-ответ или ошибка разрешения | Один результат ошибки хоста, остальные цели продолжают обрабатываться |
| Пустой набор портов | Синхронная ошибка `Scan` |
| Порт вне `1..65535` | Синхронная ошибка `Scan` |
| Обратный диапазон | Синхронная ошибка `Scan` |
| Пересекающиеся диапазоны и повторяющиеся порты | Объединяются |

DNS-имя разрешается один раз за вызов `Scan`. В качестве цели принимается IP или ASCII DNS-имя с метками до 63 символов и общей длиной до 253 символов без конечной точки. Международные имена можно передавать в Punycode. URL, запись `host:port`, CIDR и IPv6 с зоной вида `%eth0` не поддерживаются.

DNS выполняется последовательно в генераторе заданий. Уже созданные задания при этом выполняются воркерами. В результатах сохраняется первая исходная запись хоста после удаления пробелов. Фактический адрес подключения находится в `IP`.

Для ошибки DNS поля `IP == nil`, `Port == 0`, `Duration == 0`, а `Err` содержит причину. Обычно это `StateError`; таймаут DNS получает `StateTimeout`, отмена — `StateCanceled`, если такой результат успевает попасть в канал.

Входные срезы нормализуются и копируются до возврата из `Scan`. После возврата их можно изменять. Каждый результат содержит собственную копию `net.IP`. Изменять исходные срезы одновременно с выполнением самого вызова `Scan` нельзя.

## Состояния и ошибки

| Константа | Значение | Причина |
|---|---|---|
| `StateOpen` | `open` | TCP-соединение установлено и закрыто сканером |
| `StateClosed` | `closed` | Получен явный отказ в соединении |
| `StateTimeout` | `timeout` | Таймаут операции или истечение дедлайна контекста |
| `StateUnreachable` | `unreachable` | Системная ошибка недоступности сети или узла |
| `StateCanceled` | `canceled` | Явная отмена контекста |
| `StateError` | `error` | Другая ошибка |

Ошибки классифицируются через `errors.Is`, `errors.As` и системные коды, включая обёртки `net.OpError` и `os.SyscallError`. Сравнение текста ошибок не используется. Предусмотрены коды Linux и Windows. Для Windows добавлены Winsock/Win32-коды согласно [документации Winsock](https://learn.microsoft.com/en-us/windows/win32/winsock/windows-sockets-error-codes-2) и [документации Win32](https://learn.microsoft.com/en-us/windows/win32/debug/system-error-codes--1000-1299-).

`Err` сохраняет исходную причину через обёртку `%w`, поэтому вызывающий код может применять `errors.Is` и `errors.As`. При успешном подключении `Err == nil`. Ошибка закрытия уже установленного соединения не меняет состояние открытого порта.

## Конкурентность, отмена и ресурсы

На каждый `Scan` создаются генератор заданий, `concurrency` воркеров и горутина закрытия результатов. Каналы заданий и результатов имеют буфер `concurrency`. Общий семафор экземпляра `Scanner` ограничивает количество подключений во всех одновременных вызовах `Scan` и `CheckPort`.

Задания создаются постепенно, без хранения полного произведения хостов, IP и портов. Хранятся нормализованные цели, уникальные порты (максимум 65535), текущий DNS-ответ и ограниченные очереди. Каждый дополнительный одновременный вызов `Scan` создаёт собственный пул и очереди, сохраняя общий лимит подключений экземпляра.

Результаты приходят в порядке завершения. Без отмены возвращается один результат на каждую уникальную пару `IP × порт` каждого хоста, либо один результат ошибки разрешения хоста.

Медленный потребитель создаёт обратное давление: сначала заполняется буфер результатов, затем воркеры ждут чтения. Число накопленных заданий и результатов остаётся ограниченным.

При отмене прекращается создание новых заданий, отменяются текущие подключения и ожидание свободных слотов. Операции, совпавшие по времени с отменой, получают тот же отменённый контекст. После завершения генератора и всех воркеров канал результатов закрывается.

После отмены возвращается **частичный набор результатов**. Уже буферизованные результаты можно прочитать; часть готовых результатов может быть отброшена. Для ещё не начатых заданий отдельные результаты `canceled` не создаются.

Таймаут из `New` относится к одному подключению. Для ограничения всей операции, включая DNS и ожидание слотов, передавайте контекст с дедлайном. Повторное последовательное и конкурентное использование одного `Scanner` поддерживается. Глобального изменяемого состояния в пакете нет.

## Проверка

Команды выполняются из корня проекта. В `Makefile` предусмотрены две цели:

| Команда | Действие |
|---|---|
| `make full-verification` | Показывает версию Go, форматирует исходники, запускает `go vet`, обычные тесты и тесты с `-race` |
| `make test-coverage` | Запускает тесты из `tests/` с подробным выводом и `-race`, собирает покрытие пакетов `portscan/...` и `internal/...` и создаёт HTML-отчёт |


Полная проверка проекта:

```bash
make full-verification
```

Цель включает `go fmt ./...`, поэтому при необходимости изменяет форматирование исходников.

Для отчёта о покрытии кода тестами:

```bash
make test-coverage
```

Результаты сохраняются в `coverage/cover.out` (профиль покрытия) и `coverage/cover.html` (HTML-отчёт, который можно открыть в браузере). Каталог `coverage/` исключён из Git. HTML-отчёт создаётся после успешного завершения тестов. Команда `make` без указания цели запускает первую цель — `test-coverage`.

Те же проверки можно выполнить напрямую, без Makefile:

```powershell
go version
go fmt ./...
go vet ./...
go test ./...
go test -race ./...
```

Все файлы тестов находятся в отдельной папке `tests/`. Команда `go test -race ./...` запускает их из корня проекта. Строки `[no test files]` для остальных пакетов ожидаемы — их поведение проверяет пакет `tests`.

Тесты используют локальные TCP-серверы и управляемые подстановки DNS и подключения. Внешние серверы для тестов не требуются. Проверяются границы портов, дубликаты, DNS с несколькими адресами, классификация ошибок, IPv4/IPv6, закрытие соединений, общий лимит, отмена, медленное чтение, копирование данных и повторные вызовы. Реальный тест IPv6 пропускается, если система не поддерживает прослушивание `::1` или прямую проверочную попытку подключения к нему. Обработка IPv6 также проверяется независимо от сети через подстановки.

Дополнительно проверяются полный диапазон `1–65535`, крайние значения `int` в границах портов, пустые и повреждённые IP, DNS-метки длиной 63/64 символа и имена длиной 253/254 символа, пустые и некорректные DNS-ответы, обёртки ошибок, `nil` и просроченные контексты, нулевой сканер, независимость отмены одновременных сканирований, повторное использование после отмены, возобновление чтения после заполнения буфера, 1000 хостов и ошибки аргументов/вывода CLI.
